# cline-total-support-gentle-ai: total Gentle AI support for Cline, shipped as XaviCode1000/gentle-ai-cline-support

Branch `feat/cline-support-total` off upstream `origin/main` `2a3129aa`. Base work: the ODD v4 Cline migration (8 commits on `auto/cline-odd-v4-migration`, base v4.1.1) ported forward. Reference implementation for the "total support" surface: the CodeBuddy pilot (`XaviCode1000/gentle-ai-codebuddy-support`, PR #1, 68 files).
Delivery: work-unit commits on the branch; the new GitHub repo, push and PR are separate user decisions unless the spec says otherwise.

## Specs

- S1 Sandbox isolation (user, verbatim): "lo que quiero hacer con cline es lo mismo que he hecho con codebuddy : en un sandbox aislado, no instalado en mi home real". The real `~/.cline` and `~/.codebuddy` are never written by this work. Every install, sync and live test runs against an isolated `HOME` / `CLINE_DIR`.
- S2 Updated binaries (user, verbatim): "hay que actualizar los binarios de cline y gentle-ai de este trabajo". The `gentle-ai` Go binary and the Cline CLI/SDK build used by the sandbox must be rebuilt from this work's sources before any verification.
- S3 New repository (user, verbatim): "crear un repositorio en mi github gentle-ai-cline-support" and "aqui tienes el repositorio de ejemplo https://github.com/XaviCode1000/gentle-ai-codebuddy-support". The deliverable is a standalone (non-fork) public repository `XaviCode1000/gentle-ai-cline-support` holding the full upstream gentle-ai history plus the Cline support commits, mirroring the example repository's shape, with a root support document.
- S4 Total support (user, verbatim): "olvidate de codebuddy era solamente un ejemplo para copiar la metodologia y ghacerla con cline y dar soporte total a gentle-ai + cline". Cline must reach the same per-agent surface coverage as the other full-tier agents, not a partial adapter: guidance/orchestrator, Engram memory protocol, permissions overlay, persona, MCP, skills, hooks, telemetry, review assets and review transport, uninstall, doctor, install resolution, codegraph compatibility.
- S5 Reuse the existing ODD v4 work (user, verbatim): "lo que quiero hacer con cline es lo mismo que he hecho con codebuddy" plus the earlier "no escribas nada manuelmente debe ser automatico". The 8 commits of `auto/cline-odd-v4-migration` are the base and are ported onto current upstream `main`; no hand-written from-scratch reimplementation of what already exists.
- S6 No SDD-era artifacts, evidence-based close: the ODD workflow is the only workflow shipped for Cline; no SDD agent, lane script or contract test is reintroduced. Every task closes with observed evidence (build, focused test, live sandbox probe).
- S7 Workspace containment (user, verbatim): "nunca tocar los binarios de home globales, siempre trabajar en esta misma carpeta, y recuerda configurar el proyecto instalando los  paquetes necesarios , ...etc utiliza *mise*". No global binary, package or configuration is written: nothing under `~/.local/bin`, `~/.gentle-ai`, `~/.cline`, `~/.codebuddy` or any global npm/mise scope is installed or modified by this work. Every build artifact, sandbox home and runtime lives inside the workspace `/home/xavi/Projects/AI/fusion_cline_gentle-ai`, and the toolchain (Bun, Go, Node) is provisioned with `mise` inside that workspace.
- S8 Total support includes the native RDD class (user, verbatim): "quiro soporte total". The receipt-driven-development review lifecycle is part of the total support, not an optional extra: Cline becomes an RDD runtime with a reviewer transport, the advertised immutable-review capability, the standard review assets, the stop hook and the telemetry verb, exactly like the CodeBuddy reference pilot. The four runtimes that hold the class today (claude-code, opencode, codex, pi) keep their behaviour byte-identical, and the shared review contract and refusal wording stay shared.
